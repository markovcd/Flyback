From a release

Each release has a self-contained folder per platform, with the app, the command line tool, the viewer and the plugins side by side. There is nothing to install: unpack it and run Flyback.

Or let the install script fetch the latest release for your platform, check its signature and put it in place, with the command line tool and the viewer on your PATH. It runs in a terminal on Linux and macOS and in Git Bash on Windows:

curl -fsSL https://raw.githubusercontent.com/markovcd/Flyback/main/install.sh | bash

On macOS a zip downloaded in a browser will not open: the app is not notarized, so it is "damaged". Install it with the script above, or run xattr -cr Flyback.app && codesign --force --deep --sign - Flyback.app on the unpacked app.

Run it again to update. bash -s -- --uninstall in place of bash removes Flyback and everything the script added.

After that it keeps itself up to date: a new release is downloaded in the background and installed the next time Flyback starts, and only if it is signed with Flyback's release key. The window that opens then shows what changed since the version it replaced. Turn it off under Settings → Privacy.

If you switch it on, it also counts how it is used, in coarse bands: the version, the operating system, which of its own plugins loaded and which sound backend opened, roughly how big the machine is, how many of each kind of module a playing patch holds, whether an assistant was asked and which, and at the end of a run, which kinds of module were picked, how long it lasted, which of the editor's features it used and how fast the picture drew. A crash sends the kind of error and where it happened, never the message. No patch, nothing typed, and nothing that identifies you or your machine: two runs cannot be told apart from one. It is off until you tick it under Settings → Privacy.

To open .fbk, .fbkb and .fbks files by double-click, pick the editor or the viewer under Settings → Files; each kind then shows an icon of its own. A .fbkp plugin always opens in the editor, which shows what the plugin is, adds and reaches, and installs it if you say so. On macOS the build is Flyback.app, which always receives them and passes them on to the viewer if that is the choice. The command line tool and the viewer are inside it, in Flyback.app/Contents/MacOS.

The same tab sets a library folder. A sound or a picture a patch names that is not beside the patch is looked for there, and one chosen from it is named from it, so the patch finds it on any machine with the same library.

From source

You need the .NET 10 SDK. A build from source can also target Windows on Arm (win-arm64) and Intel Macs (osx-x64), which the releases do not include.

git clone https://github.com/markovcd/Flyback
cd Flyback
dotnet run --project src/Flyback.Editor.Desktop -c Release

From the command line

flyback-cli render nebula.fbk -o nebula.png --size 1920x1080 --at 2.5
flyback-cli render drone.fbk -o drone.mp4 --seconds 30 --fps 30
flyback-cli render --preset "Plasma" -o plasma.png --at 1
flyback-cli check nebula.fbk --strict
flyback-cli check nebula.fbk --triage --json
flyback-cli compare nebula.fbk nebula-ported.fbk
flyback-cli measure nebula.fbk LFO Mixer.out --seconds 10
flyback-cli print nebula.fbk -o nebula.fbks
flyback-cli print --preset "Whole band"
flyback-cli pack --preset "Mycelium" -o mycelium.fbkb
flyback-cli save --preset "Acid" -o acid.fbk
flyback-cli shot --preset "Flyback Theme" -o theme.png --at 30.3
flyback-cli shot drone.fbks -o drone.png --crop
flyback-cli ask drone.fbk "slower, and warmer"
flyback-cli tool connect drone.fbk --args '{"from": "lfo", "to": "filter1", "to_port": "cutoff"}'
claude mcp add -s user flyback -- flyback-cli mcp --editor
flyback-cli modules --find "a mirror maze of shards"
flyback-cli tutorial first-patch mine.fbks
flyback-cli decide "make the bass slower" --yes-no "Does this ask for an edit?" --json
flyback-viewer nebula.fbk --size 1080p
flyback-cli viewer --preset "No Sense Dub" --hidden --for 10
